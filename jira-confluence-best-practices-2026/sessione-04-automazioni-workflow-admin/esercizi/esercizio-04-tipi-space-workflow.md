# Esercizio 3 — Tipi di progetto e workflow

> ⏱ Tempo stimato: 25 minuti | 👥 In coppia, poi discussione di gruppo

## Obiettivo

Comprendere le differenze tra progetti Team-managed e Company-managed e analizzare i workflow esistenti.

## Istruzioni

### Parte A — Confronto tipi di progetto (10 min)

1. Apri un progetto **Team-managed** (se disponibile) e uno **Company-managed**
2. Per ciascuno, annota:
   - Dove si trovano le impostazioni del progetto
   - Se puoi modificare gli status del workflow
   - Se puoi aggiungere nuovi issue types
   - Se puoi modificare i campi delle issue
3. Compila la tabella di confronto:

| Caratteristica | Team-managed | Company-managed |
|---------------|-------------|-----------------|
| Chi può configurare il workflow? | | |
| Si possono aggiungere issue types? | | |
| I campi sono condivisi con altri progetti? | | |
| Ideale per quale scenario Tyvak? | | |

### Parte B — Analisi workflow (15 min)

1. Vai nelle impostazioni di un progetto Company-managed
2. Visualizza il workflow associato (Board settings → Workflow)
3. Disegna su carta (o su un tool online) il diagramma del workflow:
   - Quali sono gli stati?
   - Quali transizioni sono possibili?
   - Ci sono restrizioni o condizioni?
4. Confronta con il workflow di un progetto Team-managed

**Sfida extra per l'IT Manager:**
- Identifica quale workflow sarebbe ideale per i ticket IT dell'helpdesk
- Bozza uno schema con gli stati: `Nuovo → In analisi → In lavorazione → In attesa di feedback → Risolto → Chiuso`

## Risultato atteso

- Tabella di confronto compilata
- Diagramma di almeno un workflow esistente
- (IT Manager) Bozza del workflow ideale per helpdesk IT

## Domande di riflessione

- Per il vostro team, quale tipo di progetto sarebbe più appropriato?
- Quali stati mancano nei workflow attuali per gestire meglio il vostro lavoro?
